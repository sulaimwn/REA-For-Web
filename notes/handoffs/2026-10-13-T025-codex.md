## What changed
- The existing upload flow accepts `.asar`, `.exe`, `.dll` and `.apk`, case-insensitively. Browser admission and server admission share the extension list. Request/response fields and StudioProject schema are unchanged; unknown upload fields are discarded.
- Object storage, verified staging and the worker's canonical target name preserve the file kind. The reviewed worker chooses .NET, Ghidra or JADX; callers cannot select images or limits.
- Cache revision 7 partitions SHA-256 results by file kind. Renaming a cached PE to `.asar` reaches ASAR parsing and fails, rather than exposing another parser's cached result. Byte possession is still verified before every cache lookup.
- Existing authorized ASAR jobs/results in cache revisions 2–6 remain readable. New runs use revision 7. File expiry and cleanup cover all four extensions and partial uploads.
- The viewer keeps recovered Android package and .NET assembly names. Canonical fallback names are replaced only by the current authorized job's filename; cached data is not mutated.
- The local helper builds both pinned images and defaults the trusted queue to `REA_NATIVE_WORKER=1`. Operators can use `0` for the smaller Electron/.NET image. Alternate Redis ports get isolated volumes; default port 6380 preserves the original volume and queue data.
- Updated setup, architecture and current-support docs. No dependency changes. Next remains 16.3.8.

## Not done / known issues
- Hosted uploads still need the private Redis/R2 service and a long-running Docker analysis host. The static Cloudflare deployment does not gain hosted uploads just by merging this code. R2 signing is tested offline; live R2 behavior remains unverified.
- APKs/native programs are admitted by filename, then parsed inside the constrained worker. Unsupported/malformed artifacts fail without publishing a project. This does not add website URL uploads or broader native formats.
- Android missing bodies and native string-use guesses retain the R002 evidence/coverage labels. Large programs can still hit collection/resource/deadline caps.
- The local native image is large. First startup can take several minutes to build/download it.
