# T031 — Real-world sample projects (claude)

**Branch:** `claude/T031-samples` (from main @ `fef3693`)
**Status:** review.

The human asked for a couple of small real-world samples: an APK, an `.exe` and an Electron app. Uploads stay
the main point of the site; these are examples. The human approved the downloads.

## What changed
1. **Three open-source MIT apps** as demos. Sources, versions and SHA-256s are in `fixtures/sample-apps/real-world.md`.
   - Caprine 2.61.0 and jq 1.8.2 match GitHub's published digests.
   - Binary Eye came from F-Droid over HTTPS; its hash is recorded.
   - Only REA output is committed, never the binaries.

   | Demo | Kind | Analysis | Result |
   |---|---|---|---|
   | `/explore/caprine` | Electron (`app.asar` pulled out of the `.deb` in an offline container) | 331 s | 4 processes, 1 window, 15 IPC channels, 171 imports. REA marks it partial (result budget). |
   | `/explore/jq` | native `.exe` (Ghidra) | 194 s | 906 functions, 214 imports. Stripped release build, so mostly `FUN_` names. |
   | `/explore/binary-eye` | APK (JADX) | 48 s | 18 components, 11 permissions, 169 methods, 5 endpoint and 2 storage candidates (heuristic). |
2. **`fixtures/tools/sample-fixtures.mjs`** regenerates all three from local copies:
   - verifies the SHA-256s;
   - scrubs paths;
   - trims Caprine automatically.
3. **`trim-fixture.mjs`** gets opt-in options:
   - `--drop-unknown-under <prefix>`: Caprine ships unbundled `node_modules`, and 7,451 of its 7,485 REA gaps were there, so they're counted, not drawn.
   - `--keep-limitations <n>`
   - `--cap-coverage-unknown-ids`
   - `asar-entry` nodes no longer seed the module search. An entry is kept only when its file is kept.

   Existing trimmed fixtures (GitHub Desktop, VS Code) are directory inputs, so they'd regenerate unchanged.

   Caprine: full REA output 184 MB → trimmed 9.0 MB (similar to GitHub Desktop's 7.3 MB).
4. **Android adapter:** the `types` finding now says how many classes a minifier moved into the unnamed package (`defpackage.*`, excluding `R`/`BuildConfig`). Binary Eye has 2,542 of 2,800, so the map no longer silently shows only 26 app classes.
5. **Demos:**
   - three new entries in `build-demo-projects.mjs`;
   - optional per-demo `targetName`, because jq's subject name scrubs to a placeholder.
   - Demo JSON gzipped: jq 121 KB, Caprine 175 KB, Binary Eye 13 KB.

## How verified
- **Adapter:** 105 tests pass, 5 new in `tests/real-world.test.ts`:
  - Caprine: processes, window, IPC, partial coverage, no `node_modules` gaps;
  - jq: function and import counts, KERNEL32, `FUN_` note;
  - Binary Eye: components, CAMERA permission, launcher, minifier note.
- **Browser:** all three demos load with their findings and honest coverage banners.
- **Fixtures:** no personal paths in any of them.
- Full typecheck and workspace tests: see the commit.

## Not done / known issues
- **Caprine:** the trimmed sample keeps 400 module-like nodes, chosen breadth-first from processes, IPC and windows. Its own `source/` files (TypeScript via source maps) aren't all kept.
- **jq:** most functions are unnamed in the release build. That's honest, but less readable than a debug build.
