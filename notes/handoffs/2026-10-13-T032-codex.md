## What changed
- Connect the reviewed ELF worker to the upload pipeline. Browser/server admission
  accepts `.elf` and `.so` case-insensitively. Both map to canonical `elf`, so a
  `.so` upload is stored and staged as `.elf` and reaches the existing ELF parser.
- Separate admitted extensions from analysis kinds: five analysis kinds, six
  picker extensions. Browser-safe exports include `UPLOAD_EXTENSIONS` alongside
  existing `UPLOAD_KINDS`.
- Revision 7 gains an isolated `elf` result namespace. Identical ELF bytes under
  either alias can deduplicate only after download and SHA/size verification.
  Existing PE/ASAR/APK cache identities and authorized historical results retain
  their semantics; no cache revision bump is needed for this new namespace.
- Storage allowlists and raw expiry cover canonical ELF objects and partial
  uploads. The existing processor automatically stages `target.elf`, performs
  verification and cleans up; its code and the worker were not changed.
- Form/page copy, development guidance and current-support docs include Linux
  uploads. Extensionless programs must be renamed to `.elf`; `.so.1` names must
  end in an admitted extension for this explicit upload path.
- The current authorized job supplies its own display filename, including the
  `.so` alias, without changing shared cached project labels.

## How to review
1. Read `git show b529efc` through the main repository; use a separate checkout if
   the sandbox-owned folder cannot be opened by your user.
2. Run `npm run typecheck`, `npm test -w @rea-studio/pipeline`,
   `npm test -w @rea-studio/web`, then `npm run build`.
3. On a separate local stack with the native image, set `PIPELINE_TEST_ORIGIN`
   to its loopback origin and run `npm run test:http -w @rea-studio/pipeline`.
   The script still has two top-level suites, so the hosted verification script
   retains its result-count expectation.
4. After independent approval, merge this branch with `--no-ff`, preserve the
   latest T027/T030/T031 rows, mark T032 done and run full main checks. No push.

## Not done / known issues
- Live hosted uploads still need a selected Linux analysis host and private R2
  setup; this work creates neither. Live R2/TLS/systemd remain operator checks.
- This verifies the committed x86-64 ELF executable and its `.so` filename alias.
  It does not newly verify a real shared-library build, stripped/large ELF, other
  architectures, versioned filenames, Apple binaries or website URL uploads.
- Native image selection remains trusted operator configuration. The smaller
  image refuses ELF, as R004 verified. Targets are never executed; CPU/memory,
  network, process, byte/output limits and deadlines are unchanged.
