## What changed

- Reproduced a real installed-SDK behavior: `requestTimeout: 100` only logged a
  warning, and a stalled HTTP HEAD remained pending at 500 ms. Production had
  the same warning-only configuration at 60 seconds. This could hold the global
  analysis slot while awaiting download headers, cache metadata or cleanup.
- R2 HEAD/GET/PUT/DELETE/LIST operations now abort and settle their caller after
  60 seconds across attempts and retry backoff. The SDK's per-attempt timeout is
  also configured to throw. Signing upload URLs makes no network request and
  remains unchanged; the existing downloaded-byte stream limit remains 60 s.
- An abort signal alone was insufficient: SDK backoff could keep the caller
  waiting after cancellation. The cancellation race returns promptly and
  prevents later HTTP attempts. A targeted negative regression without that
  race failed at 2,079 ms against a 500-ms deadline; the corrected call settles
  around 530 ms, and the test waits past the backoff to verify no later request.
- Failed result PUTs release their local source stream. Storage timeouts have a
  sanitized internal code and a useful retry message through existing JobStatus
  fields. A failed raw deletion retains the existing cleanup-failure message;
  local staging is removed even when storage is unavailable.
- Extended the host service's stop grace from 1,850 to 2,220 seconds: 30-minute
  maximum analysis setting, five one-minute storage/transfer stages and two
  minutes of shutdown headroom. Analysis sandbox resource/time limits did not
  change. Documented storage deadlines and ambiguous PUT outcomes.
- Added six actual SDK/loopback-HTTP integration checks and a CI step. No real
  cloud credentials, remote services or target execution are involved.

## Not done / known issues

- Live R2 and the real systemd host remain unverified without infrastructure;
  the loopback service exercises the actual pinned SDK transport and retries.
- If storage rejects or times out deleting raw bytes, the object remains for
  the existing expiry sweep / required R2 lifecycle rule. The failed job does
  not claim successful cleanup.
- A PUT can have reached storage before its response is lost. No successful
  job receipt is returned on that failure; this change does not claim remote
  rollback or weaken byte-possession checks for subsequent cache reuse.
- Independent Claude review is required before merging this code. Re-run the
