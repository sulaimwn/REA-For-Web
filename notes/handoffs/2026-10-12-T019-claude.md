# T019 — UI redesign: drop the generic "AI-made" look (claude)

**Branch:** `claude/T019-ui-redesign` (from `main` @ `c9ea1a7`)
**Status:** review

The human said the UI looked obviously AI-generated. I researched the common tells and redesigned from
what the product is: a tool for reading evidence about how an app is built. The design rules are written
at the top of `apps/web/app/globals.css`. Behavior is unchanged except for the landing page and two
graph fixes (items 6 and 7).

Sources: impeccable.style/slop, capitalandcompute.net/blog/fix-ai-slop-design, 925studios.co/blog/ai-slop-design-tells,
prg.sh (purple-gradient defaults), superdesign.dev/blog/why-ai-design-looks-generic.

## What changed
1. **Palette.** Light by default, plus a graphite dark mode via `prefers-color-scheme`. Neither glows.
   - Removed the purple accent, rainbow kind colors, glow and hover lift.
   - Color now only means something: four kind families, evidence state, Studio heuristics (ochre), IPC
     boundaries (vermilion), analysis gaps (red, hatched).
   - Text contrast is AA or better in both themes.
2. **Type.** Atkinson Hyperlegible Next and Mono, self-hosted via `@fontsource-variable/*@5.3.0` (exact pins,
   OFL, no network needed at build).
   - Why these fonts: the content is paths and identifiers, where 0/O and l/1/I must be unambiguous.
3. **Kind families** replace per-kind colors. `KIND_META[kind].color` is now `.family`, in `lib/project.ts`
   (UI only).
   - Each family has a shape and a color: runtime ■, boundary ◆, system ●, code □, gap (hatched).
   - Rendered by the new `components/KindGlyph.tsx`, so kinds stay distinguishable without color.
4. **Components:**
   - Pill badges and chips are gone: `.btn` / `.btn--primary` (3px radius) replace `.chip`; plain status text replaces `.badge`.
   - Underline tabs.
   - Graph view: breadcrumbs.
   - Inspector: evidence as ruled rows with a line sample matching the graph's edge style (solid = observed,
     dashed = inferred).
5. **Landing (`app/page.tsx`)** leads with the product:
   - A short intro and a spec list (reads / shows / ask / engine).
   - The **live explorer** (`components/LandingDemo.tsx`, switchable between demos; Tiny Electron first
     because its overview is readable at a glance).
   - "How to read the map" (a legend that covers the honesty notes) and a demos *table* instead of cards.
   - Shared header and footer in `components/SiteChrome.tsx`.
   - `/open` uses the same chrome in a `.doc` layout.
6. `ProjectExplorer` / `Explorer` take `embedded` (no wordmark, no URL read or write, fills its container).
7. Graph:
   - IPC edges are no longer animated (motion only follows the user's actions).
   - Nodes get `initialWidth`/`initialHeight`: **the minimap was empty before this** (it skips nodes without a known size).
8. `docs/screenshots/*.png` re-shot in the new design: same views, from a production build.

## How to verify
- `npm run typecheck`: exit 0.
- `npm test --workspaces`: 94 pass (web 4, worker 31, cli 8, adapter 37, ask 14).
- `npm run build -w @rea-studio/web`: all 7 routes prerender.
- Browser (dev and `next start`):
  - Checked `/`, `/explore/{github-desktop,vscode-core,tiny-electron}`, `/open`, a node selection, a
    neighborhood view and the Ask tab, in light and dark mode.
  - At 390 px wide, `scrollWidth` equals the viewport (no horizontal scroll).
  - No console errors besides dev hot-reload sockets.

## Not done / known issues
- Pre-existing, not changed:
  - The graph doesn't refit when its container resizes.
  - `nodesDraggable` has no effect (controlled nodes without `onNodesChange`).
- Not run: the `impeccable` / `avoid-ai-design` CLI scanners (third-party npx packages).
