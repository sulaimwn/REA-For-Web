# T054 — Public upload admission and spending controls (Codex)

**Branch:** `codex/T054-public-upload-admission`
**Status:** review of the interface/design proposal; implementation not started
**Purpose:** make the now-working hosted uploader available to ordinary visitors
without an invite key while respecting the human's C$75/month project budget.

AGENTS.md requires agreement before changing the implemented upload API.
This note requests that agreement; no API/schema/authentication change is live.
T039's deployed private beta remains usable. Its separate Wrangler variable
patch still awaits review on `codex/T039-netcup-deployment`.

## Why a challenge alone does not bound the bill

Current `R2Store.signUpload` signs a particular key, Content-Type and length for
ten minutes. That bounds the accepted body length, but the URL is reusable until
expiry. A client can repeatedly PUT to the same object without returning to our
admission counter. This is documented behavior, not a claimed exploit measured
on production. [Cloudflare presigned URL documentation](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)

R2 charges for both stored bytes and operations. Its Standard tier includes
10 GB-month, 1 million Class A and 10 million Class B requests monthly; additional
storage is US$0.015/GB-month. Hence a job-count cap alone is not a hard spending
cap. [R2 pricing](https://developers.cloudflare.com/r2/pricing/)

The fixed server is €14.01/month (~C$22.30 at October 13's reference rate, before
card FX/tax). Keep a conservative cloud allowance below US$5/month, substantial
headroom and no autoscaling or paid Workers plan. Budgets govern this application's
usage, not unrelated services on the human's Cloudflare account.

## Proposed visitor flow

1. Choose an app; the existing browser hashing/progress remains.
2. Complete a managed Turnstile check immediately before requesting the ticket
   (after hashing, so a long preparation does not expire the challenge).
3. The upload host verifies the token and reserves bounded admission/storage.
4. Upload once to a controlled HTTPS endpoint on our fixed-price host. It verifies
   bytes/hash before one server-authorized storage write; it never parses/executes
   the uploaded app. Queue analysis still runs only in the existing Docker sandbox.
5. Complete/poll/open using the existing private bearer job token. Show queue
   capacity/limit failures clearly; the invite key is optional for the owner.

Turnstile's free tier supports unlimited checks. Validation must be server-side;
tokens are single-use, at most 2,048 characters, and valid for five minutes.
Verify exact hostname `uploads.reaforweb.com` and action `upload-app`, with a
bounded 5-second request and bounded JSON response; provider errors fail closed.
The widget secret stays server-only. A widget alone or client success boolean
must never authorize uploads. [Turnstile plans](https://developers.cloudflare.com/turnstile/plans/),
[server validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)

## Interface changes to agree

Keep `UploadRequest`, `UploadTicket`, `JobStatus`, StudioProject and cache keys
unchanged. `uploadUrl` remains opaque to clients; no storage credential is returned.

- `POST /api/uploads`: accept `X-REA-Turnstile-Token` as the public admission
  proof when public mode is explicitly enabled. Retain the existing beta-key
  owner path; both paths share the same global capacity and spending ceilings.
  Responses retain existing shapes/status semantics (403 invalid proof, 429 limit,
  sanitized 503 unavailable). Do not return provider errors or tokens in logs.
- `PUT /api/uploads/:id/file`: extend the existing local-only endpoint for a
  new controlled R2 transfer mode. An expiring random capability is tied to the
  recorded job/length/hash/kind and claimed atomically once in Redis. Concurrent
  or repeated body submissions cannot create multiple storage writes. Failed
  transfers require a fresh ticket; do not reset a consumed capability automatically.
- `POST /api/uploads/:id/complete`: retain strict Origin and bearer-job
  authorization; do not demand a second single-use challenge or a beta key from
  an anonymous visitor who already obtained a valid job token. Reads/results keep
  their existing token authorization. Knowing a SHA or job URL still grants nothing.
- Add a public-only **site key** to the server-rendered upload form props; no
  configuration endpoint or browser-visible widget secret is needed. The beta
  field remains an optional owner/invite fallback while rollout is staged.
- Proposed operator settings: public admission enabled flag (default off),
  Turnstile site/secret keys, proxy-upload signing secret, proxy trust setting,
  operation/storage budget settings. Invalid or partial public config refuses
  public admission; it must not silently fall back to unrestricted R2 tickets.

When public mode is enabled, **all new tickets**, including the owner and
pre-analysis tool, use the controlled transfer path. No direct R2 presigned PUT
fallback may remain. Existing private-beta tickets can expire before rollout.
Never serve private results through direct R2 download URLs.

## Trust boundary and bounded transfer

- Add a dedicated **web-only upload spool**, separate from worker staging, with
  mode-0600 files and mode-0700 directory. Web still receives no Docker socket,
  worker staging mount, target-execution permission or writable app code.
- Maximum two transfer slots, a conservative disk reservation before reading,
  512 MiB per admitted input, exact recorded byte/hash check and a ten-minute
  incoming-transfer deadline. Spool rather than buffering files in Node memory.
  Only after a verified body is complete does a bounded server-to-R2 write occur.
  All failures/disconnects delete the web partial file and release transfer slots;
  startup recovery removes only demonstrably abandoned spool files.
- Caddy keeps its 1 MB cap for metadata and adds the bounded large-body allowance
  only for the exact upload-file route. No generic catch-all large-body proxy.
- For per-network quotas, configure Caddy to overwrite a dedicated client-IP
  header from the actual socket peer. Trust it only on this dedicated deployment,
  where Node's port is loopback-only. Do not trust arbitrary `CF-Connecting-IP`
  or client-supplied X-Forwarded-For. Caddy ignores incoming forwarded-header
  values by default, but explicit ownership of the quota header is easier to
  verify. [Caddy header defaults](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#defaults)
- Store only expiring HMAC-derived network identifiers, never raw IP addresses;
  normalize IPv6 so changing host bits cannot trivially reset the quota. Widget
  validation need not include `remoteip`; target bytes are never sent to Cloudflare
  challenge validation. The global budget remains authoritative if identity is weak.

## Proposed initial ceilings (reviewable defaults)

- One analysis slot; existing offline/non-root/caps/filesystem/CPU/RAM/time limits
  are unchanged. No visitor-controlled resource settings.
- Public admission: 3 tickets/network/day, 25 global/day, 500 global/month,
  with bounded waiting/awaiting-transfer reservations and clear limit messages.
  Owner invitations may bypass the per-network limit, never global bill controls.
- At most **64 GiB total** retained/reserved raw and result storage. Reserve the
  full incoming size plus a conservative maximum result size before issuance;
  convert reservations to measured usage only after successful writes/deletions.
  Failed deletion retains its reservation until absence is independently confirmed.
  Existing objects must be inventoried before enabling this ledger. A missing/reset
  ledger refuses new admission until reconciliation; it must never assume empty.
- Per-month R2 SDK-operation ceilings: 100,000 Class A and 1,000,000 Class B
  attempted operations, conservatively counting/restricting retries before every
  network attempt. Include worker, API, preflight and cleanup access. All browser
  reads/writes reach R2 only through these controlled paths. No chargeable retry
  path or alternate signed URL can bypass the shared durable counter.
- Reserve cleanup capacity so ordinary admissions cannot use every operation
  slot. Bound result-download concurrency/rate separately from inexpensive
  Redis status polling. If counters/storage fail, deny further R2 operations.
- Raw one-day expiry and deletion-after-analysis remain. Existing retained
  results are **not deleted** by this proposal. When full, stop new admissions;
  further retention/deletion choices require the human's approval.

At 64 GiB, storage is roughly US$1/month at current Standard rates before tax;
the operation ceilings stay within the published free tier. This is an
application-enforced design target, not a claimed Cloudflare account billing cap.
Document billing rounding, currency/tax reserve and price-change review. Add a
small billing alert as a backstop; an alert alone is not a cap.

## Verification required before enabling

Use official test keys/mock validation only in isolated tests, never a production
fallback. Prove forged/replayed/expired/wrong-host/action challenges fail, quota
races and ambiguous Redis writes are bounded, repeated/concurrent uploads cause
one write at most, wrong bytes/hash fail, slots/spool recover after cancellation
and crashes, every SDK retry/read participates in budgets, reset ledgers fail
closed, owner bypass cannot bypass global spend, and private results remain private.
Then verify a real browser upload on the actual host with approved production
widget/exposure; the human handles any required CAPTCHA interaction. Keep a
tested rollback to beta-only. Do not remove the live beta gate before review.

No provider/widget/key changes, paid service, public admission or source/API
implementation was performed in this proposal. Documentation-only; no repeated
unit/build checks. Independent hosted ELF/Mach-O verification is recorded under T039.
