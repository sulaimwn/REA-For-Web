# T006 — Sandboxed static-analysis worker foundation (codex)

**Branch:** `codex/T006-analysis-worker`
**Status:** partial

## What changed
- Claimed T006 separately in `4c3040e`. Brought in the real T001 fixtures, then
  synced the human-merged main baseline in `2acb26b`. Main was not edited or
  merged into by Codex.
- Added a TypeScript Docker-only runner and CLI for `rea-agents@6.4.0`. It runs
  the trusted REA analyzer, never the target application. No host REA fallback.
- Added a non-root Linux image and per-job controls: no network, read-only root
  and input, no capabilities, no-new-privileges, seccomp-capable engine check,
  CPU/memory/swap/PID limits, bounded temporary storage, host/container deadlines,
  file/byte caps, and capped streaming output. No writable host mount or Docker
  socket is passed into the analysis container.
- Added resource-bounded directory/ASAR preflight inside the container. It
  rejects links, special files, unsafe archive names, nested archive entries,
  external unpacked ASAR entries, oversized headers, and out-of-range offsets.
  Genuine ASAR test archives are created using the official Electron packager.
- Streams REA stderr progress envelopes without inventing percentages. Raw
  stdout remains opaque and byte-preserved for T004. Exit zero does not imply
  complete coverage; REA warnings and partial results remain intact.
- Publishes a private result only after successful analysis and confirmed
  container removal. Cancellation, timeout, output overflow, OOM, callback
  failures, and failed cleanup discard incomplete artifacts. Uncertain container
  cleanup is reported with its generated name for operator action.
- Added worker setup/security documentation, an opt-in real Docker integration
  check, and 29 tests covering real fixture bytes, ASAR input validation, and
  simulated Docker lifecycle failures.

## Not done / known issues
- T006 is **not complete**. The image has not been built or run here; real REA
  compatibility, ASAR analysis, container permissions, resource enforcement, and
  Docker Desktop path mounting still need the integration check above. Unit
  tests use trusted fake Docker processes; they do not prove sandbox behavior.
- T004 is needed to validate/normalize the raw artifact and produce
  `StudioProject`. The worker currently returns only an internal raw-result
  descriptor. No raw REA output is exposed to UI/API code.
- REA is pinned to 6.4.0 and verified at runtime. Its transitive dependencies are
  currently resolved at image-build time rather than locked independently.
- Input must already be finalized in a private, app-owned staging directory.
  Standalone ASAR archives with external `.asar.unpacked` entries are rejected;
  upload preparation/extraction belongs to T007.
- Queue concurrency, global disk budgets, retention, and an orphan-container
  reaper belong to the deployment/coordinator. Successful artifacts remain for
  the caller to consume and remove; failed artifacts are deleted.
- No lint command exists yet. No merge to main or push was performed.
