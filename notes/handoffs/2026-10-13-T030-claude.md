# T030 — Free Ask tier (claude)

**Branch:** `claude/T030-free-ask` (from main @ `5b1634f`)
**Status:** review.

The human asked for a free Ask tier, done the way other sites do it.

**The pattern:**
- free questions with an open model, limited per visitor and per day;
- the visitor's own Claude key as the upgrade;
- subscriptions through the existing MCP connector, unchanged here.

## What changed
1. **`packages/ask/src/free.ts`** (new subpath `@rea-studio/ask/free`, no Anthropic SDK):
   - `askProjectFree` runs the same read-only Ask tools in the browser, next to the project. The project may be the visitor's own local file.
   - Each model call goes through an injected `FreeChat` (the site route).
   - Workers AI's documented function-calling convention: the chosen call as the assistant turn, then a `tool` message with its result.
   - Bounded for the model's 24k-token context: question ≤ 1,000 chars, ≤ 5 tool rounds, results cut to 6,000 chars, ≤ 48,000 chars total. Past those, it asks for a final answer without tools.
   - Unknown tool names get `runAskTool`'s "Unknown tool" result, so the model can recover.
   - `citedNodeIds` moved to `cite.ts` and is shared with the Claude loop.
2. **`apps/web/lib/free-ask.ts` + `app/api/ask/free/route.ts`:**
   - Calls `env.AI.run('@cf/meta/llama-3.3-70b-instruct-fp8-fast', { messages, tools, max_tokens: 1024 })`.
     - The server adds the fixed system prompt (Ask's, plus the tool convention) and the Ask tool list.
     - The browser can't change either, so the route isn't a general free chatbot.
     - `final: true` sends no tools.
   - **Guards:**
     - same-site Origin (URL origin, or the Host the browser used);
     - 64 KiB body;
     - message count, size and role validation (the first message must be a short user question);
     - an in-isolate per-visitor limit (12 a minute, 120 a day), plus an optional `ASK_FREE_LIMITER` rate-limit binding (documented, not configured).
   - **Workers AI's own daily free allocation:** past it, Workers AI's error 4006 maps to a friendly 429. Other errors map to a generic 502 without details.
   - No `env.AI` (`next dev`, the Linux upload host, offline preview) → 503 "use your own Claude key".
3. **`wrangler.jsonc`:**
   - `"ai": { "binding": "AI" }`.
   - A new `env.offline` without it. Workers AI bindings always need a Cloudflare login, even in local preview.
   - `cf:preview` and `Dockerfile.cloudflare-check` now use `--env offline`.
4. **Ask panel:**
   - Free is the default.
   - "Use your Claude key" opens the key form; a saved key keeps Claude as the default.
   - Model picker: Free, plus the Claude models when a key is set.
   - Privacy line: the question and looked-up details go to this site and Cloudflare; nothing is stored.
   - If free is unavailable or used up, the error opens the key form.
5. **Docs:** `docs/deploy-cloudflare.md` covers costs, the free plan's hard cap, the Workers Paid warning and how to turn the tier off, the token permission if a deploy complains, and the offline preview.

## Not done / known issues
- **Not run against real Workers AI.** That needs the human's Cloudflare login, which agents don't use.
  - The request and response shapes follow Cloudflare's docs and the model's published schema: `tool_calls: [{ name, arguments }]`.
  - First check after deploy: ask a free question on a demo. If the model's reply shape differs, `normalizeFreeReply` is the one place to adapt.
- **Quality:** Llama 3.3 70B is weaker than Claude at multi-step tool use. Answers keep the same evidence rules and citations, and the panel points to the Claude key for better answers.
- **Limits:** the per-visitor limit is per isolate. The real cost ceiling is the account's free daily allocation.
