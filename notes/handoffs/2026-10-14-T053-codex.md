# T053 — crash containment for analysis sandboxes (Codex)

**Branch:** `codex/T053-worker-crash-containment`
**Implementation:** `f82b964` + `93720f9`; includes reviewed main through `3c42789`
**Status:** review; source is not merged

## Demonstrated bug

Used a uniquely owned loopback Redis queue, private local objects, the real
production processor/runner, and checksum-verified public jq macOS bytes. Killed
only the disposable Node queue process during static Ghidra analysis. Its
sandbox, raw file and staging remained. On restart, BullMQ marked that job
failed, then started the next signed/verified tiny Electron upload. At **66.789
seconds**, both sandboxes were running despite global queue concurrency **1**.
Both retained their original 1 CPU / 2 GiB restrictions. No target was executed.
All probe processes, labeled containers, queue data and staging were removed.

## What changed

- Docker attach now supplies a private stdin channel with a fixed heartbeat
  immediately and every five seconds. Upload bytes never enter that channel;
  TTY remains disabled and the input file still has the only read-only bind.
- The image waits for an initial heartbeat before REA. EOF/disconnection stops
  the container; a connected but silent client stops it after **20 seconds**.
  Exiting its Node entry point also ends the parser descendants' PID namespace.
  The existing whole-job deadline and all CPU/memory/PID/capability/network/
  filesystem restrictions remain in force.
- Both images must carry `rea-studio.owner-protocol=1`. The runner checks this
  before container creation, and the hosted preflight checks it too. A stale
  image cannot silently ignore the new channel. Native inherits the standard
  image marker; rebuild both from the same release when deploying.
- Added permanent real-Docker regressions, `test:owner`, and its CI step after
  the image builds. Added readiness/renewal/disconnect/normal-close unit checks
  and a stale-image refusal regression.
- Documented crash behavior and matching-release updates. Hard-crash raw/staging
  still use existing 24-hour expiry. Stopped orphan container metadata is not
  automatically reaped; normal completion/cancellation still removes containers.

## Independent review / resume

Read the diff, check the owner channel is fixed and cannot be selected/disabled
by an upload request, and rerun worker typecheck/tests. Build both review images
from this branch, or use the existing isolated tags above with:

`REA_OWNER_TEST_IMAGE=rea-studio-worker:t053-owner`
`REA_OWNER_TEST_NATIVE_IMAGE=rea-studio-worker-native:t053-owner`
`npm run test:owner --workspace=@rea-studio/worker`

The actual queue probe is saved at the workspace parent's
`launch-verification/t053-crash-probe.mjs` (`T053_EXPECT_FIXED=1`). It uses
only a private disposable queue and known public fixtures. The direct HTTP
checks use the separate `t053-review-services.mjs` stack and existing suites.

Peer review is required before merge. This covers abrupt owner death or loss
of its channel; it is not a new lease-reconciliation system for every possible
Redis outage. Existing raw expiry and normal-job cleanup remain as documented.
No server, R2 credentials, public upload service, purchase or Git push was made.
