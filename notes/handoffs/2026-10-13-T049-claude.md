# T049 — jq (macOS) demo (claude)

**Branch:** `claude/T049-jq-macos-demo` (from main `006aad6`)
**Status:** review

## What changed
- **New demo `/explore/jq-macos`** ("jq (macOS)", in the landing page's "Real apps" group), built from T035's
  committed fixture `jq-1.8.2-macos.rea-6.4.0.json` with `targetName: 'jq'`. It's a 12.25 MB JSON, under
  Cloudflare's 25 MiB per-asset limit, and brotli shrinks it like `jq.json` (11.8 MB → ~170 KB on the wire).
- **"Starts at jq's own main":** on macOS the loader calls `main` directly (LC_MAIN), and Ghidra names it `entry`.
  It calls `setlocale`, `getenv`, `isatty`, `strcmp`, `strtol` and `dirname`, which matches jq's `main()`.
- **Overview ordering (follow-up to T045, `apps/web/lib/entry-tree.ts`):** named parts come before Ghidra's
  `FUN_`/`SUB_`/`LAB_` placeholders. Within each group, callees that link onward still come first.
  - Before: jq for macOS's 40-node overview was `entry` plus 39 `FUN_…` functions, with no library calls at all,
    because the generic functions were the ones that "link onward".
  - Now: `entry` → its libSystem calls → its functions.
  - Windows jq is barely affected: its entry starts in the C runtime.
- **Import titles (`apps/web/lib/project.ts` `displayName`):**
  - Native imports now read `function (library file)`, e.g. `_setlocale (libSystem.B.dylib)` or
    `GetStdHandle (KERNEL32.DLL)`. Before it was `library!function`, which graph cards truncated to
    `/usr/lib/libSystem.B.dylib!_se…`.
  - Imports without a library (ELF) are unchanged. The inspector still shows the full library field.
  - No code or tests depended on the old format.
