## Problem and fix

- Reproduced both live paths in the browser: the main Cloudflare site answers
  with Llama 3.3 70B, one lookup and three real IPC citations. The same question
  on `uploads.reaforweb.com` fails with the explicit missing-model 503. Local
  Node previews have the same missing Cloudflare binding. The model itself works.
- Browser transport now sends upload-host and exact HTTP loopback conversations
  directly to `https://reaforweb.com/api/ask/free`. Other deployments retain their
  same-origin endpoint. Graph tools still run locally beside the map.
- The canonical service permits only the exact HTTPS uploads origin and HTTP
  `localhost`, `127.0.0.1`, `[::1]` origins. Strict POST/Content-Type preflight;
  no wildcard or credentialed CORS. Normal same-origin callers still work.
- Success and normal error responses retain readable CORS headers. Private job
  referrers, upload-session credentials and cookies are omitted by the browser.
  Calls reach Cloudflare directly so visitor IP limits remain per visitor.
- Fixed prompt/tools, model, context/body limits and free allowance are unchanged.
  No proxy secrets, new API keys, paid services or sandbox changes.
- JSON request/response and StudioProject shapes are unchanged. TypeScript's
  import-extension option is enabled only in the no-emit web app so the common
  transport/policy module also runs in native Node tests. Docs describe the fix.
