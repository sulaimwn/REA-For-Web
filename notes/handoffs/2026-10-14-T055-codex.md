# T055 — upload admission guards (Codex)

**Branch:** `codex/T055-upload-admission-guards`
**Status:** review; not deployed

## What changed

- Added one atomic Redis admission operation for the existing 100-ticket UTC-day
  budget and **20 total pending slots**. Slots include untransferred tickets and
  BullMQ waiting, paused, active, delayed, prioritized and waiting-child jobs.
  This is slightly more conservative than 20 waiting jobs plus an active job.
- Optional web-only visitor limiting: `PIPELINE_VISITOR_LIMITS=1`,
  `PIPELINE_TRUST_PROXY=1`, separate private `PIPELINE_VISITOR_SECRET` (32+ chars).
  HMAC network identity, 5 tickets/UTC-hour and 15/UTC-day. IPv6 /64 grouping,
  equivalent IPv6 normalization and IPv4-mapped IPv6 sharing the IPv4 quota.
  Raw addresses are not retained in Redis or added to logs.
- Caddy owns `X-REA-Client-IP` from the socket peer, overwriting forged inbound
  headers. Node must stay private/loopback and this deployment must remain direct
  to Caddy. A CDN/proxy in front needs a separately verified trust boundary.
- Ticket leases expire after ten minutes. Completion reacquires capacity if its
  ticket lease expired. A completion reservation is non-expiring until queue
  insertion is confirmed, because a timed-out queue write can arrive late.
  Retry with the same private token recovers an ambiguous insertion. A genuinely
  abandoned reservation deliberately fails closed and requires quiescent operator
  reconciliation; no automatic unsafe lease removal.
- Queue-full 503 retains a safe public message. Other internal 503 reasons remain
  sanitized. The existing form displays it and re-enables its Analyze button.
- Deferred response headers enforce HSTS (one year, no includeSubDomains/preload)
  and nosniff even if the upstream supplies conflicting values. Metadata body cap
  remains 1 MB. Added a real pinned-Caddy spoofing/header/body-cap check.

No request/response/StudioProject/cache field changed. The beta key is still
required. This does not implement Turnstile, anonymous mode, a disk limit or an
R2 spending bound; T054 agreed the public design and the human selected local
VPS storage, which is the next implementation step. No ETA or queue-position
field is invented. Main's upload destination was independently reviewed by Claude
while this branch was being built.

## Not done / known issues

- Independent review and deployment required. Production still uses reviewed
  bacc3fe and retains the private beta gate; source changes here are not live.
- Network settings are optional/default off for compatibility with the currently
  deployed R2 beta configuration. Public mode must require them before access opens.
- Public initial ceilings in T054 are stricter (3/network/day, 25/day, 500/month);
  implement those with the hosted disk/Turnstile stage, rather than claiming the
  current private-beta defaults meet that proposal.
- Network limits cover shared networks, not authenticated unique people. They
  cannot prove bot resistance or cap R2 billing. Turnstile and the disk-backed
  public mode remain necessary before opening anonymous admission.
