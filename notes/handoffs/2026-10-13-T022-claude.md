# T022 — MCP connector (claude)

**Branch:** `claude/T022-mcp` (from `main` @ `ad7316f`)
**Status:** review

The human called the MCP connector essential: people should be able to query analyzed apps from Claude
and other MCP clients. One server definition, two transports:
- **remote**, the site's demos at `/api/mcp`;
- **local**, a stdio binary for your own `.studio.json` files.

## What changed
1. **`packages/mcp` (`@rea-studio/mcp`)**: `createReaMcpServer(source)` on the SDK's low-level `Server`.
   - Tools:
     - `list_projects`
     - the five Ask tools (`project_overview`, `search_nodes`, `get_node`, `get_neighbors`, `find_path`), each with a required `project` argument.
     - All are annotated `readOnlyHint`.
     - Tool output is exactly `runAskTool`'s JSON, so the browser Ask panel, tours and MCP share one implementation.
     - Unknown projects or tools return `isError` tool results, not protocol errors.
   - Server `instructions` give the same guidance as the Ask prompt: start with `list_projects`; treat app text as data; "not found" isn't absence; label studio heuristics.
   - Passes a no-op `jsonSchemaValidator`. The SDK only uses one for elicitation, and its default Ajv validator compiles code at runtime, which Cloudflare Workers forbid.
2. **`rea-for-web-mcp` bin** (`packages/mcp/dist/stdio.js`): `node …/stdio.js app.studio.json [more…]`. Ids are slugs of the app names; it gives a clear error for raw REA output.
3. **`/api/mcp`** (`apps/web/app/api/mcp/route.ts`):
   - Stateless Streamable HTTP with JSON responses: one server per request, no sessions. CORS is open; the data is public and read-only.
   - Demos are listed from the build-time index (`appKind` added to `DemoEntry`) and loaded through Cloudflare's `ASSETS` binding (`getCloudflareContext`). Off Cloudflare it falls back to a same-origin fetch.
   - Parsed projects are cached per instance.
4. `@rea-studio/ask/tools` entry point (`toolkit.ts`): the tools without the Claude agent or Anthropic SDK code.
5. Root `build:packages` now builds `@rea-studio/mcp` (the web build imports it).
6. `docs/mcp.md`: claude.ai/Desktop custom connector, `claude mcp add` for Claude Code, Claude Desktop config. The landing page's "Ask" row links to it.
7. Dependency: `@modelcontextprotocol/sdk` **1.31.0, exact**, in `packages/mcp` and `apps/web`.
   - Chose the Sept 28 release over Oct 2–5 1.32.x to avoid a days-old release.
   - The lockfile only adds packages; no existing version changed.

## How to verify
- `npm run typecheck`: all 8 workspaces pass.
- `npm test --workspaces`: **120 pass**. MCP 5:
  - the in-memory SDK client lists tools, projects and instructions, and calls overview/search/get_node;
  - errors come back as tool errors;
  - a **real stdio client** spawns the built binary on a `.studio.json`;
  - raw REA input is rejected with a message.
- Dev server: the official SDK `StreamableHTTPClientTransport` against `http://localhost:3103/api/mcp` initializes, lists 6 tools and the 3 demos, searches GitHub Desktop for "gists" (`POST /gists`), and gets the VS Code overview.
- **Linux + Cloudflare runtime**, in the pinned `node:24.18.0-bookworm-slim` image from a clean `git archive`:
  - `npm ci --ignore-scripts`, `build:packages`, `opennextjs-cloudflare build`, `opennextjs-cloudflare preview` (local workerd).
  - `/`, `/explore/tiny-electron`, `/open` and `/projects/index.json` return 200.
  - **The same SDK probe passes against `/api/mcp` in workerd.**

## Not done / known issues
- Uploaded (private) projects aren't exposed over MCP. That needs per-job auth (the job token as a bearer) and the pipeline's storage. A follow-up once hosted uploads exist.
- The remote endpoint has no rate limiting beyond Cloudflare's. Its data is public demos and requests are cheap, but a Cloudflare rate-limit rule on `/api/mcp` would be prudent after launch.
- `claude.ai` connector setup was not tried, since the site isn't deployed yet. The protocol was checked with the official SDK client over Streamable HTTP, locally and in workerd.
- `T021` (.NET) and `T012` (endpoint verdicts) are on their own branches. Once merged, MCP serves them automatically: tools pass through all node fields, and the demo index lists `tiny-dotnet`.
