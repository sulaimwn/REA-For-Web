## What changed
- Implements T027's proposed operator cache preparation through the existing
  upload/queue path. `scripts/preanalyze-cache.mjs` hashes one local file, optionally
  checks an expected release SHA, requests a signed ticket through `UploadControl`,
  transfers the file, completes the upload and waits for the normal worker.
- Shared orchestration is in `packages/pipeline/src/preanalyze.ts`; it is a trusted
  host module, not a browser export or public endpoint. No API/schema changes,
  new dependencies, direct cache imports or demo-to-cache conversion.
- Uses normal admission, the existing 100-ticket/day quota and global queue
  concurrency of one. The queue worker still chooses the image and limits.
  Every cache reuse goes through the existing fresh-byte possession verification.
- Local mode uses its real signed `LocalStore.receive` validation and needs no
  web server. R2 mode streams PUT with the signed headers/declared length, refuses
  redirects and bounds transfer by the signed-link lifetime. Tokens and signed
  URLs stay internal; source paths, provider errors and credentials are not logged.
- Wrong release digests fail before admission/upload. Unsubmitted upload failures
  clean their raw object. Once completion has been attempted, only the worker or
  expiry sweep owns cleanup: an ambiguous completion response may still have
  queued the job. Interruption stops waiting without deleting a queued input.
- Waiting is interruptible, bounded by existing upload expiry. CLI graceful
  connection shutdown has a two-second fallback that disconnects only this
  operator's Redis clients if QUIT is stuck; it does not stop a worker/job.
- `npm run cache:seed -- <file> [--sha256 <digest>]` builds packages first via its
  pre-script. The direct Node command supports an explicitly loaded private
  worker environment. Setup and retention behavior are in `docs/uploads.md`.
- CI runs the new real Redis suite after the existing queue-outage suite because
  each suite's write pause needs the dedicated disposable service.

## Limits / follow-ups
- No live R2/host exists here. Object streaming is verified against a controlled
  loopback HTTP server and existing offline signing tests; live R2 permissions,
  CORS, TLS and lifecycle behavior remain unverified operator checks.
- This prepares exact complete app files in a configured service. It does not
  seed the live site, automatically download popular apps, import T031 demo
  subsets, grant public cache/hash access, or guarantee instant first uploads.
- Source changes between hashing and transfer cannot publish a result for the
  requested hash: local transfer or the normal worker rejects the changed bytes.
- CLI interruption can still consume an admission ticket or leave a job record;
  normal expiry applies. An already queued analysis continues normally.
- Claude owns T030 Ask, T031 real-app demos and T033 landing work. Those source
  files were not touched; this adds only operator/pipeline tooling and its docs.
