# T005 — Static demo explorer (claude)

**Branch:** `claude/T005-demo` (built on `claude/T004-adapter`, so merge T004 first or together)
**Status:** review. Codex, please review per AGENTS.md step 5.

## What changed
- `apps/web/scripts/build-demo-projects.mjs`: runs the adapter on the committed fixtures and writes
  `apps/web/public/projects/{github-desktop,tiny-electron}.json` + `index.json` (gitignored). It runs
  automatically before `dev` and `build` (`predev` / `prebuild`).
- `/`: landing page with the demo cards and an honest "what it can and can't tell you" section.
- `/explore/[slug]`: static (SSG) explorer with three panes:
  - **Left:** search across all nodes; **Findings** (one row per category: count, or "not found",
    with an unresolved badge; click to list the items and REA's notes), **Source** (tree of files
    recovered from source maps), **Files** (shipped file tree), and analysis gaps.
  - **Middle:** React Flow graph. *Architecture overview* by default (processes, windows, bridges,
    IPC, native add-ons, storage, workers, plus the files that link them). Double-click a node, or select it
    from the sidebar or inspector, to see its *neighborhood* (capped at 60 neighbors; the rest are listed in the inspector).
    IPC links are amber and animated; inferred links are dashed.
  - **Right:** inspector with kind-specific facts, every evidence record (observed/inferred,
    confidence category, `file:line:col`, extractor, REA's limitations) and clickable relations.
  - **Top:** coverage badge plus a partial-analysis banner (files that lost relationships, gap count,
    "not found may still exist", and the trimmed-fixture note).
- `apps/web/lib/graph-view.ts`: never draws the whole graph. Overview = each connected component laid
  out with dagre (top-to-bottom or left-to-right, whichever is closer to square), lone nodes in a grid,
  blocks shelf-packed. Neighborhood = hub layout (incoming left, focus center, outgoing right).
- New deps (exact pins, both published over 2 weeks ago): `@xyflow/react@12.12.0`, `@dagrejs/dagre@3.1.1`.
  The web app also depends on `@rea-studio/rea-adapter` (build-time script only).

## How to verify
- `npm run dev` from the root, then open http://localhost:3000. (I used port 3100 to avoid clashes.)
- Root `npm run typecheck` and `npm run build` pass; both explore pages prerender as static HTML.
- Adapter tests are still green (22 pass).
- Checked in the browser:
  - **tiny-electron:** the overview shows package → main → window → preload → handlers → channels.
    Clicking `notes:save` shows its 2 evidence records (`src/preload.js:4:18`, `src/main/main.js:17:0`).
  - **GitHub Desktop:** the overview packs 36 nodes. A dynamic channel shows "unknown at static
    time" with REA's limitations. The source tree shows `app/src/{lib,models,ui}`. Search →
    `keytar.node` focuses its neighborhood. The `renderer.js` hub view is readable.
  - No console errors on a fresh load of either page.

## Not done / known issues
- The demo uses the **trimmed** GitHub Desktop fixture (910 of ~2,700 Studio nodes); the banner says so.
  The full 50 MB raw output isn't committed. To show the full app, generate it locally and add it to `DEMOS`.
- No URL state yet (selected node / focus aren't in the URL, so views can't be linked).
- No heuristics (T009): the endpoint list is REA's raw candidates, labeled "unfiltered".
- Desktop-first. Narrow screens stack the panes, but the graph isn't great on a phone.
- No README GIF or screenshots yet.
