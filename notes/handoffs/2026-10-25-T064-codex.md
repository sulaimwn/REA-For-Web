## What changed

- Audited official 6.8 release and actual installed tool contracts. Most breaks
  affect tools the website does not use. Kept complete native/Android inputs;
  no arbitrary retained errors become successful results.
- Pin REA 6.8 in CLI and isolated analysis runtime. Lockfile version changes are
  REA plus new protobuf/msgpack packages only; unrelated versions unchanged.
- REA now requires Node `^22.23.4 || ^24.22.1 || >=26.12.1`. Updated root/CLI
  engines, both analysis images, web/Cloudflare images, CI and setup docs.
  Node 24.22.1 archives verified against official SHA-256; official Docker index
  pinned to `55fb5f5a527ea2c5c4a95f963e48ef90aa38c7b346054fdc8ee9957a2b55d205`.
  Staged private Node runtime `/opt/rea-node-v24.22.1` on server. Global Windows
  and server Node installations remain unchanged; services use the private runtime.
- Cache namespace `rea-6.8.0-adapter-10`; readers retain 6.4 revisions 2–7,
  6.5 revision 8 and 6.7 revision 9 across all supported file kinds.
- Fresh real Electron ASAR and .NET fixtures. Historical evidence remains
  untouched. Electron is 28 nodes/60 links: upstream removed one duplicate
  preload mapping; all three bridge-to-channel paths remain intact.
- REA 6.8 now projects internal managed calls with site counts/opcode histograms.
  Fold matching member-inspection calls into projected links, preserving their
  IDs, evidence and counts; keep external API enrichment. Retain upstream partial
  coverage and omission limits. The optional no-members case still shows projected
  calls honestly. Legacy 6.4–6.7 outputs continue through their existing path.
- JADX JAR remains 0.7.1 with same hash; packaged REA bridge is now 7 (was 4).
  Ghidra 12.1.4 and JDK 21 remain unchanged. No new upload formats advertised.
