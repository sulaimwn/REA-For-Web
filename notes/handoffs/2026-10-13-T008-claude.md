# T008 — Recover relationships REA's whole-app budget drops (claude)

**Branch:** `claude/T008-recover` (from `main` @ `ad7316f`)
**Status:** review

In big apps REA 6.4.0's shared result budget drops the relationships of most files
(`application_projection_failure: resource_constraint`). In GitHub Desktop 3.6.5, 139 of 179 files kept
only 2 structural edges each. Analyzed on its own (the file, its `.map`, and the root `package.json` at the
same relative paths in an empty folder), every one of them comes back complete. This branch measures that,
merges per-file runs into the whole-app project, and does it automatically in local mode.

## Measurements (GitHub Desktop 3.6.5, this machine: 8 CPUs, 15.5 GB)
- Isolating all 139 affected files, 3 at a time: **398 s wall, 0 failures**.
  - Slowest: `crash.js` 65 s, `copilot/sdk/index.js` (2.9 MB) 42 s, `main.js` 24 s. Most small files take a few seconds.
  - One REA worker peaked at about 1.1 GB.
- Merging all 139 runs into the whole-app project: **150 ms**. Results:
  - **Files with lost relationships: 139 → 0.**
  - Nodes 2,683 → 3,260, links 3,461 → **4,298 (+837)**.
  - Findings: imports 769 → **1,328** (+73%), IPC channels 4 → 7, endpoint candidates 89 → 101, storage 9 → 10, workers 1 → 2.
  - 0 dangling links, 0 duplicate ids; re-applying adds nothing.
- Not fixed by isolation: windows still 0, because REA doesn't follow webpack's `r.BrowserWindow` alias (limitation 1, upstream draft in `docs/upstream`).

## What changed
1. `packages/rea-adapter/src/recover.ts`: `recoverDroppedRelationships(base, runs)` returns a new project.
   - It imports everything reachable from the file in its own run, but never the app's structure (file, package, process, source map, source file nodes), which the whole-app run has right.
   - Matching:
     - files by path;
     - external modules by their shared `external-module:<specifier>` id;
     - literal IPC channels by name, so cross-file pairing still works;
     - everything else by kind + label + first evidence location.
   - Merged nodes gain the new evidence and IPC usages.
   - Recovered files get `analysisIssue: null`; `filesWithAnalysisIssues` and findings are recomputed, and a limitation line says how many files were re-analyzed.
   - **No schema change.**
2. `@rea-studio/rea-adapter/file`: `extractedArtifactRoot` reads `rea extract-artifact`'s output folder, so the CLI never interprets REA JSON itself.
3. CLI (`apps/cli`): after the whole-app run, files with dropped relationships are re-analyzed automatically.
   - 2 at a time, biggest first; an `.asar` is unpacked once with REA's own extractor and the folder is deleted afterwards.
   - A file whose run fails keeps its whole-app facts.
   - Paths from REA output are checked so they can't escape the scratch folder.
   - `--no-recover` skips it. The summary says how many files were recovered.
   - `runRea` now takes a command and an optional quiet mode.
4. Fixtures:
   - `github-desktop-3.6.5.isolated.{main.js,crash.js}.rea-6.4.0.json`: real per-file runs, temp folder scrubbed.
   - Tool: `fixtures/tools/isolate-files.mjs`.

## Not done / known issues
- **Uploads (Codex's worker):** not wired in. Proposal:
  - Inside the same `--network=none` container, after the whole-app run, re-analyze files the adapter reports with `analysisIssue`.
  - The target is already mounted read-only, and an `.asar` can use `rea extract-artifact` into the container's tmpfs.
  - Adapt each run with `adaptReaFile`, then `recoverDroppedRelationships`.
  - It needs its own time budget: GitHub Desktop's recovery is about 7 min at 3-wide, on top of the 82 s main run. Perhaps cap recovery by total bytes or time and keep the rest as `analysisIssue`.
  - Bump the result cache revision so cached projects get recovered.
- `ipcSummary` still describes the whole-app run only (REA's counts). The IPC finding count is rebuilt from nodes, so it does include recovered channels.
- Isolated runs see each file alone, so a file's relationships to *other files* (relative imports between app files) resolve as "not found" in its own run. The merge only takes what's reachable without crossing into app structure, so it doesn't import those as fake externals. Those links remain missing.
- Conflicts to expect: `claude/T021-beyond-electron` also edits `apps/cli/src/cli.ts` (`runRea` generalized the same way) and `packages/rea-adapter/src/file.ts`. Both are additive; merge by keeping both.
