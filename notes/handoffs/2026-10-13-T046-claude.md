# T046 — Faster program analysis: job CPUs as an operator setting (claude)

**Branch:** `claude/T046-analysis-cpus` (from main `3b1fef5`)
**Status:** review

## Measurements (upload speed)
- **Where program-analysis time goes:** one REA MCP session on jq 1.8.2 for Windows (local Ghidra 12.1.4):
  - `open_binary` 0.3 s, then the first `list_procedures` **204 s**. That's Ghidra's import and auto-analysis,
    which REA runs on first use.
  - 200 `procedure_callees` calls took **1.0 s** in total, about 5 ms each.
  - So the worker README's "about 0.2 s per callee call" known limit was wrong. The per-function collection
    isn't the cost.
  - REA's `get_call_graph` (one forward traversal from `entry`: 613 procedures, 15 levels, 0.7 s) loops over
    `procedure_callees` inside REA. It would save little, so the collector is unchanged.
- **CPUs:** the same in-image collection of jq 1.8.2 for macOS (`collect-native-in-image.mjs`, `--memory=2g`) gave
  identical bundles every time:

  | `--cpus` | seconds (runs, in order) |
  |---|---|
  | 1 | 139, 124 (plus 134 and 145 from earlier T035 runs) |
  | 2 | 57, 52, 54 |
  | 4 | 42 |

  The order was interleaved (1/2/4, then 2/1/2), so it isn't a warm-cache effect.
- **APK (Binary Eye 1.75.5 through the worker's real `runWithDocker`, private `claude-t035` image):**
  1 CPU took 90 and 165 s, 2 CPUs 162 and 109 s, 4 CPUs 74 s. That's too noisy to claim a 2-CPU gain, so the
  docs say so.
- REA exposes no Ghidra analyzer or CPU options. Its headless command runs the default auto-analysis. Fewer
  analyzers would be an upstream REA change.

## What changed
- `apps/worker/src/limits.ts`: `queueLimitsFromEnv` reads **`REA_ANALYSIS_CPUS`**. It's an operator setting
  only, validated by the existing `resolveLimits` range (0.1–4). The **default stays 1**: the sandbox's resource
  default is a policy choice, so I'm proposing the deploy value instead of changing it.
- `apps/worker/tests/worker.test.ts`:
  - The default is 1, and `"2"` yields `--cpus=2` in the container arguments; `"1.5"` is accepted.
  - `0`, `5`, empty, `two`, `-1` and `Infinity` are refused.
- Docs: `docs/uploads.md` documents the setting and the measurements. In `apps/worker/README.md`, the wrong
  "known limit" is replaced by the measured facts.
