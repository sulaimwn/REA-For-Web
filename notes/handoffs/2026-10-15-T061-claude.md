# T061 — Upgrade REA 6.4.0 → 6.5.0 (claude)

**Branch:** `claude/T061-rea-6.5.0` (from main `cee057e`)
**Status:** in progress. Code, tests and docs are done; the real container check is pending because Docker Desktop
wasn't running.

## Why
REA 6.5.0 (released 2026-10-14) adds features that matter here:
- partial results when analysis fails or runs out of time;
- Ghidra analyzer overrides, a possible speedup;
- selecting a thin slice of universal Mach-O;
- Electron fuses;
- better JS code-split and package-alias recovery.

It also has breaking output changes. JADX 0.7.1, Ghidra 12.1.4 and the Node engines are unchanged, so the
heavy image layers are the same.

## What changed
- **Pins:**
  - `rea-agents` 6.5.0 in `apps/cli` and `apps/worker/rea-runtime` (both lockfiles updated);
  - `REA_VERSION` and the worker image tags (`rea-studio-worker[-native]:rea-6.5.0`);
  - the Dockerfile version gate and the native `BASE_IMAGE`, CI workflow tags, `scripts/dev-uploads.mjs`,
    the fixture tools and the hosted-uploads docs.
- **Cache:** new results go to `results/schema-0.1.0-rea-6.5.0-adapter-8/<kind>/…`. `safeKey` still accepts the
  REA 6.4.0 adapter 2–6 and adapter-7 namespaces, so published results stay readable.
- **Adapter compatibility for 6.5.0 output:**
  - New `call-paths.ts`. REA 6.5.0 traces each contextBridge member to its IPC call as `javascript-expression`
    nodes (namespace `electron-call-path-step`: exposure → function → terminal, one `path_id`). These used to
    fall through as 9 bogus `analysis-gap` nodes. Now the steps are folded and each path becomes one REA edge
    `bridge-api --invokes|sends--> ipc-channel`.
    - The edge keeps REA's evidence: `inferred`, since REA marks these paths `candidate`.
    - Details: `operation`, `side: renderer` and `pairingBasis`. No schema change.
    - Report fields `foldedCallPathSteps` and `callPathLinks` record what was folded and linked.
  - `ReaNode.identity` and a nullable `source_map_reference.source_name` added to the REA types. The adapter
    already falls back to the label when the name is null.
  - The P/Invoke verification and `get_call_graph` breaking changes don't touch inputs we read.
- **Landing engine line:** "REA 6.5.0". `ARCHITECTURE.md` and the uploads docs name the current pin. Historical
  "derived from 6.4.0 fixtures" notes are unchanged, and demos stay on their 6.4.0 fixtures, labelled as such.
