# T035 — macOS programs (Mach-O) (claude)

**Branch:** `claude/T035-macho` (fast-forwarded to main `9320bff`, then this work)
**Status:** review

## What changed
- **Real fixture** `fixtures/samples/jq-1.8.2-macos.rea-6.4.0.json` (5.5 MB): jq 1.8.2's macOS release
  `jq-macos-amd64` (MIT; SHA-256 `e94b266e…f00bc0`, recorded in `fixtures/sample-apps/real-world.md`).
  - Collected with REA's Ghidra provider inside the native worker image (no network, program mounted read-only,
    never run) via the new `JQ_MACOS` step in `fixtures/tools/sample-fixtures.mjs`. That took 134 s.
  - Local paths are scrubbed: `<INPUT_PATH>` replaces them, and no home path survives.
  - REA reports `format: "mach-o"`, `architecture: "x86_64"` and `available_architectures: ["x86_64"]`, plus
    1,797 procedures (1,667 functions, 130 externals), 2,206 strings and 1,667 callee queries.
- **Adapter** (`packages/rea-adapter/src/native.ts`): REA's `"mach-o"` maps to the schema's existing `macho`.
  No schema change. Any other value is still refused.
  - Mach-O imports name their library (`/usr/lib/libSystem.B.dylib::_name`), so the existing "Libraries:" note
    applies. The ELF-only limitation stays ELF-only.
  - Ghidra lists each import stub as a thunk, so the project has 1,537 function nodes plus 130 imports.
  - Ghidra's `entry` is flagged as the entry point.
- **CLI** (`apps/cli/src/cli.ts`):
  - `programHeader()` recognizes ELF and thin Mach-O (`cffaedfe`, `cefaedfe`, `feedfacf`, `feedface`). Mach-O
    takes the ELF path: REA's Ghidra on a Linux/macOS host, with the same Windows explanation.
  - Universal binaries (`cafebabe` followed by an architecture count under 45) get a "pick one architecture
    with `lipo -thin`" message. Java class files share `cafebabe`, but their version field is 45 or more,
    so they stay unsupported files.
- **Worker** (`apps/worker`):
  - Preflight signatures can list several magics; `macho` accepts the four thin ones.
  - `.macho` (for renamed extensionless programs) and `.dylib` map to the `macho` kind. The kind is a
    program kind, so it runs in the native image and goes to Ghidra like ELF.
  - The standard image refuses it with "macOS programs need the native analysis worker".
- **Docs:** `docs/targets.md` (a macOS section), `apps/worker/README.md`, `AGENTS.md` (target list),
  `real-world.md`.

## Not done / known issues
- **Uploads:** the pipeline's `UPLOAD_KINDS` doesn't include macOS yet. Like T032 did for ELF, that's a pipeline task:
  add a `macho` kind for `.macho`/`.dylib`, with its own cache namespace.
- **No demo page yet.** `jq-1.8.2-macos` could become `/explore/jq-macos`, but the landing page should only
  advertise macOS once uploads take it.
- **Universal binaries are refused.** REA's `available_architectures` suggests it can pick one, but there's no
  universal sample to test. A small MIT universal release would be a download to approve first.
- **`.app` bundles** are directories with Info.plist and resources, not covered here. Analyze the binary in
  `Contents/MacOS/`.
