## What changed

- Real Redis reproduction: with healthy connections already established,
  `CLIENT PAUSE` leaves admission and completion pending beyond 6,500 ms.
  `connectTimeout` and `maxRetriesPerRequest` do not bound a live socket that
  stops replying. No unrelated queue was paused.
- Added five-second command deadlines to both web-side Redis connections
  (upload records/admission and the BullMQ producer). The producer also fails
  offline commands instead of holding them. Worker reconnect behavior, bounded
  progress writes, global concurrency and all analysis limits remain unchanged.
- Quota increment and expiry now run atomically. A timed-out command can still
  execute at Redis after its reply deadline; it must not leave a permanent daily
  admission key because a later EXPIRE was never sent. The 100/day limit remains
  unchanged and uncertain admissions are conservatively counted.
- Dedicated integration coverage verifies read/write deadlines, subsequent
  protocol use, quota expiry after an uncertain write, raw-byte preservation,
  token protection, retrying the same completion, and exactly one queued job.
- Updated the existing worker-outage test to handle a possible API timeout and
  unpause only after proving raw/staging cleanup happened during the outage.
  It still verifies a failed result, no published cache, and a later successful job.
- Added the dedicated Redis API test to CI, sequentially after worker queue tests
  and before operator pre-analysis. Documented command deadlines and retry rules.
