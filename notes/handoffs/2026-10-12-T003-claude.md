# T003 — StudioProject schema (claude)

**Branch:** `claude/T003-schema` (based on `main` @ `00cc1ba`, which has T001 + T002 merged)
**Status:** review

## What changed
- `packages/schema/src/index.ts`: StudioProject v0.1.0 types plus runtime constant
  lists (`EVIDENCE_STATES`, `CONFIDENCE_LEVELS`, `COVERAGE_STATUSES`,
  `FINDING_CATEGORIES`, `NODE_KINDS`, `RELATIONS`, `STUDIO_SCHEMA_VERSION`).
  - Evidence keeps REA's `state`, categorical `confidence`, `authority`, `extractor`,
    `location`, `limitations`. No numeric scores.
  - `origin` on every node/edge: `rea` vs `studio-heuristic` (with `heuristic` + `basis`).
  - `findings[]`: per-category `found` / `not-found` / `confirmed-absent`, with
    `unresolvedCount`, `coverage`, `notes`. The adapter should never emit
    `confirmed-absent` from REA 6.4.0 static analysis.
  - Gaps: `analysis-gap` nodes, `FileNode.analysisIssue`, `analysis.coverage`,
    `analysis.limitations`, `analysis.filesWithAnalysisIssues`.
  - `source-file` (recovered from source maps) is a separate kind from shipped
    `file` / `module` / `bundle-chunk`.
  - Semantic graph and export-shape nodes are left out; `analysis.omitted` records it.
  - A compile-time check fails the build if `NODE_KINDS` misses a node kind (verified
    by removing one).
- `ARCHITECTURE.md`: replaced the draft schema with the real one, design rules, a full
  REA → Studio mapping table for T004 (with observation counts), and an example built
  from real fixture values. Also corrected the pipeline command to `--format json`.
- `fixtures/README.md`: limitation #2 now quotes REA's own message confirming the result
  budget is shared ("The parent reserved its remaining result capacity…").
- `TASKS.md`: T003 → review; added T008 (per-file bundle analysis), T009 (adapter
  heuristics), T010 (draft upstream issues) as unowned `todo`.

Every enum value in the schema was observed in the fixtures (I enumerated every
property key/value across tiny-electron and the full 50 MB GitHub Desktop output) or
comes from REA's CLI `--schema` (`format: 'asar'`).

## How to verify
- `npm ci && npm run typecheck` from the repo root: passes for all four workspaces.
- Read the mapping table in `ARCHITECTURE.md` against `fixtures/samples/*.json`.

## Not done / known issues
- No adapter, so the schema hasn't round-tripped a full fixture yet. T004 is that test.
  If T004 hits a REA shape the schema can't hold, change the schema in T004 and note it.
- Classification order for multi-observation `javascript-module` nodes ("first matching
  row in table order") is a reasonable default, not something verified against every
  node. T004 should test it.
- No API pagination types yet. A full GitHub Desktop project will be ~11 MB of nodes/edges;
  the graph API can project subsets later.
