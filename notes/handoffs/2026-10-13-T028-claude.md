## What changed
1. **Sample with an answer key:** `fixtures/sample-apps/tiny-linux/`.
   - `tiny_notes.c`, built by `build.sh` with gcc 12 in the pinned Debian Node image, the same approach as `tiny-native`'s mingw.
   - `tiny-notes` is a 16.7 KB x86-64 ELF, committed and never run.
   - Fixture: `fixtures/samples/tiny-linux.rea-6.4.0.json`, REA 6.4.0 + Ghidra 12.1.4.
2. **Collection happens inside the native worker image.** REA's Ghidra provider on Windows refuses ELF: "Windows Ghidra P0 accepts PE targets only" (`target_format_unsupported`).
   - `fixtures/tools/collect-native-in-image.mjs` runs the adapter's existing `collectNativeBundle` inside `rea-studio-worker-native`. It runs offline, mounts the sample read-only and writes only `/out`.
   - `target-fixtures.mjs` calls it with `NATIVE_IMAGE=1`.
3. **Adapter** (`native.ts`, small changes):
   - `target.format` now comes from REA's `subject.format` (`pe`, `elf`, `macho`) instead of a hard-coded `pe`.
   - Ghidra's `<EXTERNAL>::name` imports get an empty `library` and are labeled by symbol, not with an invented library.
   - `_start` counts as an entry symbol.
   - ELF-specific notes in limitations and findings.
   - Codex's R002 heuristic labels are untouched.
4. **Schema (additive):** `TargetInfo.format` gains `elf` and `macho`. `NativeImportNode.library` is documented as empty for ELF.
5. **UI and Ask:** imports with no library show the bare symbol. The inspector explains "not recorded (ELF names only the symbol; the dynamic linker picks the library)". Demo `/explore/tiny-linux`.
6. **CLI:** an extensionless or other file starting with `\x7fELF` is a Linux program.
   - On Windows: a clear error naming Linux/macOS hosts or the analysis worker.
   - Elsewhere: requires `GHIDRA_INSTALL_DIR`, then runs the same collector.
7. **Worker:** new target kind `elf` (from `.elf` or `.so`).
   - Preflight checks the `\x7fELF` header.
   - Mounted read-only at `/input/target.elf`.
   - Native image only; the standard image refuses with `invalid_input`.
   - The entrypoint goes straight to Ghidra through a shared `analyzeNative`, the same code path as native PE.
   - Sandbox flags are unchanged.

- **Big programs:** still one `procedure_callees` call per function (T027 notes).
