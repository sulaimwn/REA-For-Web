# T012 — Endpoint plausibility verdicts (claude)

**Branch:** `claude/T012-endpoints` (from `main` @ `072b4d6`)
**Status:** review

Implements the interface Codex agreed in `2026-10-12-T015-codex-review.md`:
- an optional `assessment` on endpoint candidates, as a Studio inference;
- REA nodes and evidence untouched;
- unassessed candidates visible;
- users can reveal every candidate.

## What changed
1. **Schema:** `EndpointNode.assessment?: EndpointAssessment` = `{ verdict: 'plausible' | 'unlikely'; heuristic; basis }`. Optional and additive.
2. **Adapter** (`heuristics.ts`, `endpoint-shape`):
   - **Plausible** when the value is an http(s)/ws(s) URL, or `METHOD /path`, or a `/path` passed to a `fetch`/`request` call. Renamed bindings count, e.g. `call:l.fetch` or `call:client.request`.
   - **Unlikely** otherwise, with a specific reason:
     - a key passed to `.get/.set/.has/.delete` (map, header or env lookup)
     - a string in a `path` property
     - an empty string
   - Report: `endpointVerdicts`.
   - The endpoints finding keeps REA's candidate count, and its notes say how many look real.
3. **UI:**
   - The endpoints list shows plausible (and any unassessed) candidates, with a "Show N unlikely REA candidates" toggle. Unlikely rows are tagged.
   - Neighborhood graphs skip unlikely candidates and count them in "N more neighbors hidden (see inspector)".
   - The inspector shows "Studio verdict (endpoint-shape): Plausible/Unlikely… <basis>". Relation lists tag unlikely candidates and sort them last.
4. **Ask:** `get_node` already returns all node fields, so the verdict reaches the model. Search ranks unlikely candidates last; plausible endpoints are no longer penalized.

## Not done / known issues
- The rule is shape-based. A real endpoint built at runtime (e.g. `` `${base}/repos` ``) shows as unlikely or doesn't appear at all, because REA reports only literal values.
- `T021` (on its own branch) adds websites, whose `analyze-web-bundle` endpoint candidates are just as noisy. When both merge, the web-bundle adapter should reuse `assessEndpoint`.
- Pipeline cache: uploaded results cached before this change have no `assessment`. The UI treats them as unassessed, so they stay visible. Codex may bump the cache revision so fresh uploads get verdicts.
